# 异常处理和告警系统使用指南

> **创建时间**: 2026-01-17  
> **目的**: 说明新增的异常分级系统和 Telegram 告警配置

---

## 🎯 系统概述

新增了三级异常处理系统：

1. **CRITICAL** 🔴 - 必须立即停止策略
2. **WARNING** ⚠️ - 发送告警但可继续运行
3. **INFO** ℹ️ - 仅记录日志

---

## 📋 异常类型

### 🔴 CRITICAL 异常（会停止策略）

#### 1. `HedgeFailed`
**触发条件**: 对冲订单失败  
**影响**: 产生单边敞口，价格风险暴露  
**行为**:
- 发送 Telegram 告警
- 抛出异常停止策略
- 记录详细日志

**示例**:
```
🚨 HEDGE FAILED - SINGLE-SIDED EXPOSURE!
Aster: SELL 0.002 @ 4596.00
Backpack hedge failed: Failed to place hedge order on backpack
Strategy MUST stop to prevent further exposure.
```

#### 2. `InsufficientMarginForHedge`
**触发条件**: 对冲端保证金不足  
**影响**: 无法对冲新仓位  
**行为**: 同上

#### 3. `PositionImbalance`
**触发条件**: Aster 和 Backpack 仓位不平衡超过阈值  
**影响**: 表明对冲失败或遗漏  
**行为**: 同上

---

### ⚠️ WARNING 异常（仅告警）

#### 1. `QuoteOrderFailed`
**触发条件**: 做市订单失败  
**影响**: 减少做市深度，但无额外风险  
**行为**:
- 发送 Telegram 告警（如果失败率 ≥ 50%）
- 记录日志
- 继续运行

**示例**:
```
⚠️ High Quote Failure Rate
3/6 quote orders failed (likely insufficient margin)
Details:
  failed: 3
  total: 6
  placed: 3
  failure_rate: 50.0%
```

#### 2. `InsufficientMarginForQuotes`
**触发条件**: 做市端保证金不足  
**影响**: 无法挂新单  
**行为**: 暂停做市，继续监控

#### 3. `PriceFeedStale`
**触发条件**: 价格数据过期  
**影响**: 可能导致错误报价  
**行为**: 暂停做市直到恢复

## 🔧 Telegram 告警配置

### 1. 创建 Telegram Bot

1. 在 Telegram 中找到 [@BotFather](https://t.me/BotFather)
2. 发送 `/newbot`
3. 按提示设置 bot 名称
4. 保存返回的 **Bot Token**（格式：`123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11`）

### 2. 获取 Chat ID

1. 在 Telegram 中找到 [@userinfobot](https://t.me/userinfobot)
2. 发送任意消息
3. 保存返回的 **Chat ID**（格式：`123456789`）

或者：
1. 先给你的 bot 发送一条消息（如 `/start`）
2. 访问：`https://api.telegram.org/bot<YOUR_BOT_TOKEN>/getUpdates`
3. 在返回的 JSON 中找到 `chat.id`

### 3. 配置环境变量

在 `.env` 文件中添加：

```bash
# Telegram Alerts (optional)
TELEGRAM_BOT_TOKEN=123456:ABC-DEF1234ghIkl-zyx57W2v1u123ew11
TELEGRAM_CHAT_ID=123456789
```

**注意**: 如果不配置，告警系统仍会工作，但只会记录日志，不会发送 Telegram 消息。

## 🔍 代码示例

### 在策略中使用异常

```python
from .exceptions import HedgeFailed, QuoteOrderFailed
from .alerts import send_critical_alert, send_warning_alert

# CRITICAL: 对冲失败
if not hedge_order:
    send_critical_alert(
        title="HEDGE FAILED",
        message=f"Cannot hedge {fill.qty} {fill.side}",
        details={'order_id': fill.order_id}
    )
    raise HedgeFailed(fill_info=fill_info, error="Order failed")

# WARNING: 做市失败
if failed_orders > threshold:
    send_warning_alert(
        title="High Quote Failure Rate",
        message=f"{failed_orders} orders failed",
        details={'failed': failed_orders}
    )
```

## 🎯 最佳实践

### 1. CRITICAL 异常使用原则

**应该使用 CRITICAL 的情况**:
- ✅ 对冲失败（产生单边敞口）
- ✅ 对冲端保证金不足
- ✅ 仓位严重不平衡
- ✅ 关键系统故障

**不应该使用 CRITICAL 的情况**:
- ❌ 做市订单失败（不影响已有仓位）
- ❌ 价格数据延迟（可以暂停做市）
- ❌ 网络临时中断（可以重试）

### 2. WARNING 异常使用原则

**应该使用 WARNING 的情况**:
- ✅ 做市订单失败率高
- ✅ 做市端保证金不足
- ✅ 价格数据过期
- ✅ 性能降级

### 3. 告警频率控制

为避免告警轰炸，建议：
- 同类型告警 5 分钟内最多发送 1 次
- CRITICAL 告警立即发送
- WARNING 告警可以批量发送

## 🚨 紧急情况处理

### 收到 CRITICAL 告警后的步骤

1. **立即检查仓位**
   ```bash
   python scripts/check_positions.py
   ```

2. **如果有单边敞口，立即对冲**
   ```bash
   python scripts/emergency_hedge.py
   ```

3. **检查日志**
   ```bash
   tail -n 100 market_maker.log
   ```

4. **分析原因**
   - 保证金不足？→ 充值
   - API 问题？→ 检查 API 状态
   - 网络问题？→ 检查连接

5. **修复后重启**
   ```bash
   python run_xau_arbitrage.py
   ```
